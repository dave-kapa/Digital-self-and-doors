# DIGITAL SELF & ATTENTION DOORS
## Libreto maestro narrativo del juego del webinar

**Versión 1.0 — Agosto de 2026**  
**Propósito:** fuente de verdad para el contenido que verá el jugador durante la experiencia.  
**Uso:** este documento define la historia, los textos de pantalla, las bifurcaciones narrativas, los contenidos de Analizar/Revisar/Actuar y los cierres de cada caso. La lógica de puntajes, maquetación, animaciones y comportamiento técnico se parametriza aparte en Antigravity.

---

# 0. Cómo debe leer Antigravity este documento

Existen tres tipos de contenido:

### `[JUGADOR]`
Texto que sí aparece en pantalla.

### `[ANTIGRAVITY]`
Instrucción interna para la plataforma. **No debe mostrarse al jugador.**

### `[FACILITACIÓN]`
Idea o mensaje que se mostrará en resultados o servirá para el debrief verbal. Puede proyectarse como apoyo, pero no forma parte del texto que el jugador debe leer mientras decide.

---

# 0.1 Regla para los cierres

Cada caso tiene tres posibles outros:

1. **Resultado positivo**
2. **Resultado neutro**
3. **Resultado negativo**

`[ANTIGRAVITY]` La lógica que determina qué outro recibe cada jugador dependerá del sistema de puntajes que se defina posteriormente. **Solo debe mostrarse uno de los tres. Nunca los tres.**

El juego completo tiene igualmente tres finales posibles. Solo debe mostrarse el final correspondiente al resultado global configurado.

---

# 0.2 Indicadores ocultos de las alternativas de acción

Cada acción tiene un indicador interno. **No debe ser visible para el jugador.**

- **1 — Necesaria / útil:** ayuda de manera directa a resolver la situación o recuperar agencia.
- **2 — Neutra / innecesaria:** no resuelve el problema central, pero tampoco incrementa de forma significativa la exposición.
- **3 — Riesgosa:** aumenta la exposición, cede agencia o agrava el problema.

`[ANTIGRAVITY]` En el Caso 2 el indicador cambia según la variante legítima o maliciosa del mensaje.

---

# 0.3 Principio narrativo

FARO no es un villano.

Fue diseñada para detectar amenazas, aprender y operar con el máximo de capacidad posible. El incidente ocurre porque encuentra una ruta legítima para ampliar sus permisos: **las propias decisiones de los operadores**.

El juego no trata de destruirla. Trata de **recuperar agencia sobre FARO y aprender a trabajar con ella sin cederle completamente criterio, supervisión, límites y responsabilidad.**

### Lo que deja este caso

- “Parece legítimo” no significa “está verificado”.
- “Me parece sospechoso” tampoco prueba que exista una amenaza.
- La lectura interna sirve como señal para revisar, no como autenticación.
- Cuando la apariencia no alcanza, necesitamos **verificación independiente**.

`[JUGADOR]`

- En un entorno de IA, los mensajes pueden ser impecables y aun así falsos.
- Las señales internas ayudan a reconocer que algo necesita más revisión.

# ANEXO C — REGLA DE TONO

Todo texto narrativo debe cumplir cinco criterios:

1. **Breve:** una pantalla debe poder leerse rápidamente durante un webinar.
2. **Claro:** el jugador debe saber qué está pasando sin explicación externa.
3. **Tenso, no apocalíptico:** FARO es una capacidad fuera de gobernanza, no un monstruo.
4. **No moralizante:** una mala decisión no convierte al jugador en ingenuo o irresponsable.
5. **Coherente con el cierre:** la IA pasa de ser parte del incidente a convertirse en una posible aliada bajo condiciones de agencia, supervisión y entrenamiento.

# ANEXO D — REGLA DE CONTINUIDAD NARRATIVA

Después de cada caso debe ocurrir siempre la misma secuencia:

4. una breve intervención de FARO;
